```markdown
# Rules DSL Specification

## One Idea
A simple boolean rule evaluator that takes variable bindings and evaluates expressions like `price > 100 and region == "EU"`.

## Design Decisions
- **Stateless evaluation**: expressions are pure functions of their variables; no side effects.
- **Errors as values**: unbound names, type mismatches, and comparison errors propagate as `Miss` objects.
- **No implicit coercion**: `"5" + 1` is an error, not `"51"` or `6`.
- **Strict short-circuiting**: `and`/`or` evaluate left-to-right; right side evaluated only if needed.

## Grammar (precedence low → high)
```
expr       := or_expr
or_expr    := and_expr ("or" and_expr)*
and_expr   := not_expr ("and" not_expr)*
not_expr   := "not" not_expr | comp_expr
comp_expr  := primary ((CMP) primary)*
primary    := NUMBER | STRING | IDENT | "(" expr ")"
CMP        := "==" | "!=" | "<" | ">" | "<=" | ">="
```

## Exit Codes
- `0`: evaluation succeeded, result printed
- `1`: rule evaluated to false (or error)
- `2`: lex/parse error

## Literals
- **Numbers**: `42`, `3.14` (no `_`, `nan`, `inf`)
- **Strings**: `"hello"` (no escape sequences)
- **Identifiers**: `price`, `region` (alphanumeric + `_`, starts with letter)

## Operators
- **Comparison**: `==`, `!=`, `<`, `>`, `<=`, `>=` (type-sensitive)
- **Logical**: `and`, `or`, `not` (require boolean operands)

## Sample Programs
```
price > 100 and region == "EU"
not (x == 0)
a == b or c == d
```
```
