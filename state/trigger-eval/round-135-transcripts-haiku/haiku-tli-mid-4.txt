```markdown
# Rules DSL Specification

## Idea
A boolean expression evaluator for filtering/validation rules. Users write expressions like `price > 100 and region == "EU"` to evaluate against data contexts.

## Design Decisions
- **Total evaluation**: Errors propagate as values (Miss type), never raise exceptions
- **Simple operators**: Comparison (==, !=, <, >, <=, >=), logical (and, or, not)
- **Variables**: Identifiers resolved from evaluation context
- **Type coercion**: Strict typing; type mismatches yield errors
- **Nesting depth limit**: Parser enforces max 100 nesting levels

## Grammar (Precedence: Low → High)
```
expr      → or_expr
or_expr   → and_expr ('or' and_expr)*
and_expr  → not_expr ('and' not_expr)*
not_expr  → 'not' not_expr | cmp_expr
cmp_expr  → primary (cmp_op primary)?
cmp_op    → '==' | '!=' | '<' | '>' | '<=' | '>='
primary   → NUMBER | STRING | IDENT | 'true' | 'false' | '(' expr ')'
```

## Error Handling
- **Miss type**: Represents runtime errors with reason strings
- **missed(x)** predicate: Test if value is an error
- **Unbound variable**: "variable X is not defined"
- **Type mismatch**: "cannot compare X and Y"

## Exit Codes
- 0: Success
- 1: Evaluation result is error/false
- 2: Lex or parse error
```
