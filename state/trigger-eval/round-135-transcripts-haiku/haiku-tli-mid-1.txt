# Rule DSL — Expression Evaluator

**One idea:** Evaluate boolean config rules with variables, comparisons, and logic operators.

**Grammar (low→high precedence):**
```
expr    → or_expr
or_expr → and_expr ("or" and_expr)*
and_expr→ not_expr ("and" not_expr)*
not_expr→ "not" not_expr | cmp_expr
cmp_expr→ primary ((== | != | < | <= | > | >=) primary)*
primary → IDENT | NUMBER | STRING | "true" | "false" | "(" expr ")"
```

**Design decisions:**
- Error-as-value: unbound variables and type errors return `Miss` objects, not exceptions
- Evaluator is total; no exceptions for user errors
- Parens required for operator precedence (no chaining comparisons)
- Exit codes: 0 success, 1 runtime error (Miss), 2 lex/parse error

**Error story:**
- `Miss(reason)` propagates through all operations
- `missed(v)` predicate tests if result is an error
- Missing variables → "name 'x' not found"
- Type errors → "cannot compare <type> and <type>"
