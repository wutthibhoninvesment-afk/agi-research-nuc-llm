This is a classic tree-walking interpreter limitation—each guest-level recursion becomes a Python call-stack frame. You have a few approaches, in order of complexity:

**1. Iterative evaluation with an explicit stack (simplest)**  
Replace recursive AST traversal with an explicit evaluation stack. Instead of `eval(node)` recursively calling `eval(child)`, push work items onto a stack and process them in a loop. This fully decouples guest recursion depth from Python's limit.

**2. Bytecode compilation + stack VM (best long-term)**  
Compile the AST to bytecode and run a stack-based VM. Guest code becomes loop iterations, not call frames. This is what production interpreters (CPython, V8) do and scales to arbitrary recursion depth.

**3. Trampolining (middle ground)**  
Instead of direct recursion, have eval return a thunk (closure) that the caller invokes. This defers the call, but Python's still tracking frames—marginal help.
